# Video to Guide 使用说明

把一段软件操作录屏，自动转成「带截图 + 时间戳 + 操作说明」的图文手册（Markdown / HTML）。
全部处理在本机完成，视频不会上传到任何外部服务。

## 一、运行前必须准备好的东西

**只有一样是必须的：一个 OpenAI 兼容的模型服务。**

| 组件 | 是否必需 | 用途 / 说明 |
| --- | --- | --- |
| 模型服务 | **必需** | 看截图 + 整理步骤。本机免费方案（LM Studio / Ollama / llama.cpp / vLLM 任选）或云端 API Key |
| FFmpeg | **不需要** | 视频信息读取和抽帧都已内置（PyAV）。只有内置读取打不开某些冷门格式时才会去 PATH 找它兜底 |
| 语音识别 | **已内置** | faster-whisper + small 模型都在包里。只有视频**有旁白**时才会用到；无音轨的录屏不会走这条路 |

一条命令全部检查（软件环境 / AI 服务分开显示）：

```
vtg doctor
```

输出分两组：

```
[软件环境]        ← 这里 ✗ 才是真的装坏了
[AI 服务]         ← 这里 ! 只是模型服务没启动，不影响打开已有手册、编辑和导出
```

软件环境全绿就能用。AI 服务显示 `!` 时，启动模型服务（或去设置里填 API Key）后重新检查。

## 二、准备模型（本地 / 云端，可分别指定）

本软件不绑定任何一家模型，走 **OpenAI 兼容接口**。设置窗口（右上角「设置…」或 `Ctrl+,`）
里服务商分两类：

| 分类 | 包含 | 特点 |
| --- | --- | --- |
| **本机服务（免费）** | LM Studio（12345）、Ollama（11434）、自定义本地服务（vLLM / llama.cpp 等） | 免费、不上传、要自己先启动服务。**默认就用这个** |
| **云端服务（API）** | OpenAI、Claude、Gemini 等 | 按 token 计费、填 Key 就能用、不占显卡、不需要显卡 |

**「看截图」和「写步骤」是两个独立的任务角色**，可以分别指定来源——
例如识图用本机 LM Studio，写步骤用云端 DeepSeek，互不影响，改一个不会覆盖另一个。

无论选哪一类，拿到模型的顺序都一样：

1. 选服务商（地址会自动填好，可改）；
2. 点 **「获取模型」**（只查列表，不发推理请求、不花钱）；
3. 在列表里选中一个模型 → 点 **「设为视觉模型」** 或 **「设为步骤模型」**；
4. 点 **「测试连接」**（地址通不通、Key 对不对）；
5. 点 **「测试视觉调用」**（真发一张 48×48 的纯色测试图，验证它到底能不能看图）；
6. 点 **「保存」**，下次分析生效。

### 2.1 本地模型（免费，默认方案）

需要自己启动一个带视觉能力的本地服务。三种常见做法（任选其一，都免费）：

| 方案 | 启动方式 | 默认端口 |
| --- | --- | --- |
| LM Studio | 装好后在「Developer」页点 Start Server | 12345 |
| Ollama | `ollama pull <模型>` 之后保持 `ollama serve` 运行 | 11434 |
| llama.cpp | `llama-server -m <模型文件> --mmproj <视觉投影文件> --port 8080` | 8080 |
| vLLM / 其他 | 只要兼容 OpenAI 接口即可，端口随意 | —— |

关键点：

- **模型必须支持图像输入**（多模态）。纯文本模型能写步骤，但看不了截图；
- 具体用哪个模型、什么参数量、什么量化，按你自己机器上的实际情况选——本文**不指定型号**。
  模型更新很快，显存需求也因规模而异（大致参考：小模型 4-bit 量化 6～8 GB 显存起步，
  更大规模需要更多显存；CPU 也能跑但会明显慢）；
- llama.cpp 必须带 `--mmproj`，否则只加载语言部分，看不了图；
- 端口写进软件「设置 → 模型配置 → 接口地址」即可，不要求一定是 12345。

服务起来之后，在设置窗口里：服务商选「本机服务（免费 · OpenAI 兼容）」→ 地址填上一步的
端口 → 点「获取模型」。列表里会出现服务端真实的模型 ID（llama.cpp 返回的是 `.gguf` 文件路径，
这是正常的），用途列会显示「支持视觉（服务商声明）」，说明服务端自己声明了它能读图。

### 2.2 其他模型（API，填一个 Key 就能用）

适合没有好显卡、或想让识图更快更准的情况。操作：

1. 打开软件 → 右上角 **「设置…」**（或菜单 工具 → 设置，快捷键 `Ctrl+,`）；
2. 服务商下拉里挑一家云端（OpenAI、Claude、Gemini 等；列表见「设置 → 模型配置」，
   也可以选「自定义本地服务」填任意 OpenAI 兼容地址）；
3. 点 **「获取 Key」** 会打开该厂商的密钥页面，注册后复制 Key 贴进输入框；
4. 点 **「获取模型」** 拿到这个账号实际能用的模型列表（只查列表，不产生费用）；
5. 选中一个模型 → 「设为视觉模型」/「设为步骤模型」；
6. 点 **「测试连接」** 看地址和 Key 通不通，再点 **「测试视觉调用」** 确认它真的能看图；
7. 点 **「保存」**，下一次分析生效。

注意事项：

- **DeepSeek 目前没有视觉模型**，只能用它的文本模型；识图请选别家，界面上也会给黄色提示。
- 火山方舟多数情况要填「推理接入点 ID」（ep- 开头）而不是模型名，以控制台为准。
- 厂商可能调整地址或模型名，所以输入框都是**可编辑**的，随时能改；旁边的「官方文档」按钮会打开对应文档。
- 云端按 token 计费，一段 2 分钟视频通常消耗很少（一次分析约 8 张图 + 一段文本）。

### 2.3 模型列表里的「来源」和「用途」怎么读

| 列 | 显示 | 含义 |
| --- | --- | --- |
| 来源 | 服务商 | 从接口真实查到的模型 |
| 来源 | 手动 | 你自己填的模型 ID（不代表一定能调用，需要实测） |
| 用途 | 支持视觉（服务商声明） | 服务端元数据声明支持图像输入，可以信 |
| 用途 | 支持视觉（预设） | 命中软件内置的已知视觉模型名单 |
| 用途 | 未验证 | 没有可靠依据，名字里带 vl 也不算，请点「测试视觉调用」实测 |

关于**隐藏**：

- 隐藏只影响本软件列表里显不显示，**不会卸载或删除任何模型文件**，也不会调远端接口；
- 隐藏按「服务商 + 模型 ID」分别记录，重启后仍然有效；
- 隐藏**正在使用**的模型时会先弹窗问你，并且不会自动换成别的模型——避免你不知情时结果就变了；
- 勾选「显示已隐藏」可以随时恢复。

**不支持自动列模型的服务商**（目前是火山方舟、千帆、混元）按钮会变灰，并提示用「手动添加…」
自己填模型 ID——这是它们的接口限制，不是软件坏了。

## 三、两种用法

### 3.1 桌面界面（推荐）

```
vtg gui
```

![界面](evidence/ui-main.png)

窗口分三块，顶部工具栏按操作阶段分组：**选片与分析**（选择视频… / 开始分析 / 取消）、
**结果操作**（编辑步骤 / 删除步骤）、**导出与查看**（导出手册… / 打开手册 / 重新生成手册 / 输出目录）、
**历史记录**。灰掉的按钮表示当前状态不能做（比如还没分析完就不能导出）。

**左栏**

- 顶部信息卡：文件名、时长、分辨率、有无音轨、字幕条数、截图张数、几个步骤待核实；
- 「操作步骤」页：每行显示序号、标题、起止时间戳，带 ⚠ 的是依据不足的步骤；
  上方搜索框可按标题或说明过滤；
- 「历史记录」页：之前每次分析一行，显示视频名、完成时间、步骤数、状态，**双击重新打开**。

**右栏**

- 「步骤详情」：截图 + 时间范围 + 操作 + 预期结果 + 依据（哪句字幕、画面里有什么）。
  同一屏的近似截帧只显示一张，避免详情越滚越长；
- 「全部字幕」：Whisper 转出来的全部句子和对应时间；
- 「运行日志」：这次分析每个阶段的耗时、警告和错误。出问题先看这里。

操作顺序：

1. 点「选择视频…」，选一段本地录屏（mp4 / mkv / mov / avi / webm 都行）；
2. 点「开始分析」，顶部出现进度区：进度条 + 当前在处理什么 + 七个阶段走到哪一步；
3. 分析中可以点「取消分析」，会在当前阶段结束时停下；
4. 左栏点某一步，右侧看截图、操作说明和依据；双击（或「编辑步骤」）可改标题、操作、
   预期结果和待核实状态；按 Delete 或「删除步骤」可删；
5. 改完或删完，手册会立即重新生成，不需要手动点；
6. 点「导出手册…」选一个目录，会把 guide.md、guide.html、steps.json 和 frames/ 一起拷过去；
7. 关掉软件后想再看，直接在「历史记录」里双击。

### 3.2 命令行（适合批量处理和排查问题）

```
vtg analyze "D:\录屏\我的视频.mp4"          # 分析，默认目录名按时间生成
vtg analyze "视频.mp4" --run-id 我的教程      # 指定输出目录名
vtg analyze "视频.mp4" --force                # 忽略已有中间结果，全部重算
vtg analyze "视频.mp4" --no-vision            # 只用字幕、不调视觉模型（模型服务没开时的应急方案）
vtg list                                      # 看历史运行记录
vtg export 我的教程                           # 改了 steps.json 后重新生成 md/html
```

## 四、输出文件说明

每次分析生成一个任务目录，**成品和工作数据分开**：

```
runs/<运行目录名>/
  project.json          任务元信息（结构版本、源视频、创建时间）
  output/               ← 成品：拷走这个目录就能看手册
    guide.html          单文件 HTML 手册，双击打开，点步骤跳到视频对应时间
    guide.md            Markdown 手册
    frames/             手册引用的截图
  .work/                ← 工作数据
    steps.json          结构化操作步骤，**这是唯一的数据源**
    transcript.json     带时间戳的语音转录
    frames.json         每张截图的时间点和画面变化分数
    vision.json         视觉模型对每张截图的观察结果
    timeline.json       字幕、画面、时间三者对齐后的时间线
    run_report.json     本次处理的状态、耗时、警告和错误，出问题先看它
    analysis/           外部解析工具的原始输出（只有用了外部工具时才有）
```

**重要**：`steps.json` 是数据源，`output/` 里的两份手册都是由它渲染出来的。
手工改完步骤后执行 `vtg export <目录名>` 就会重新生成。

### 4.1 导出的手册包

导出的文件夹按「视频 / 批次」分层，批次目录本身就是成品包：

```
Exports/
  我的录屏/                  ← 视频分组（默认用视频文件名）
    20261101-053012/         ← 批次（默认日期-时间）
      我的录屏.html  .md  frames/  steps.json  manifest.json
    20261101-053012-2/       ← 同名批次自动加序号，旧的永不覆盖
```

命名规则在「设置 → 导出」里改，可用占位符：`{video} {date} {time} {run_id} {title}`。
每��导出前还会弹一个对话框，那一次可以临时改名字。

### 4.2 旧任务目录

以前的版本把 JSON 和手册平铺在任务根目录下。新版本读取时会自动认这种旧结构，
**不用先迁移也能打开**。想把旧目录整理成新结构，执行：

```
vtg migrate --dry-run   # 先看会做什么，不改任何文件
vtg migrate             # 真正执行：复制到新位置，旧文件移到 .work/_legacy/（不删除）
```

## 五、常见问题

### 提示「连不上本地模型服务」

模型服务没启动，或者端口不对。检查 `http://127.0.0.1:12345/v1/models` 能否打开；
如果你用的端口不是 12345，在 `config.json` 里改 `llm_base_url`。

### 视觉阶段全部失败，但字幕正常

多半是模型没有视觉能力（漏了 `--mmproj`，或者装的是纯文本模型）。
这时程序会降级成「只用字幕」继续跑，并在 `run_report.json` 里写明原因——
这不是成功，只是降级，步骤质量会明显下降。

### 视频没有音轨 / 没有语音

程序不会崩，会跳过转录、只用画面继续分析，并在报告里记一条警告。
没有语音的录屏，步骤标题会比较笼统，需要人工补充。

### 分析出来的步骤时间不对

先看 `timeline.json` 里截图的时间点对不对。截图主要来自画面变化检测，
如果视频里有大量滚动、动画、鼠标移动，可能触发过多或过少的截图，
可以调 `config.json` 里的 `max_frames`。

### 路径里有中文

已完整支持，包括中文目录、中文文件名、文件名里带空格。

## 六、配置文件

项目根目录的 `config.json`（没有就自己建）可以覆盖默认设置，例如：

```json
{
  "connections": {
    "lmstudio": {"base_url": "http://127.0.0.1:12345/v1", "api_key": ""},
    "openai":   {"base_url": "https://api.openai.com/v1", "api_key": "sk-..."}
  },
  "vision_role": {"provider": "lmstudio", "model": "<你的模型目录>/gemma-4-12B-it-QAT-Q4_0.gguf"},
  "text_role":   {"provider": "openai",   "model": "gpt-4o-mini"},

  "whisper_model": "small",
  "whisper_language": "zh",
  "read_long_edge": 768,
  "max_frames_auto": true,
  "disable_thinking": true
}
```

字段含义：

| 字段 | 作用 |
| --- | --- |
| `connections` | 每家服务商只存一份「地址 + Key」，两个任务角色共用 |
| `vision_role` | 看截图用谁：`provider` 是服务商 id，`model` 是模型 ID |
| `text_role` | 写步骤用谁，格式同上 |
| `read_long_edge` | 送进视觉模型前把截图长边缩到多少像素（小字看不清就调大） |
| `max_frames_auto` | `true` = 按视频时长自动算截图上限（时长÷3+30，夹在 60–240 之间）；`false` 时用 `max_frames` |

**旧配置兼容**：以前只有一套 `llm_provider / llm_base_url / llm_api_key / llm_model / vision_model`
的 `config.json` 仍然能直接用——启动时会自动补成「连接 + 两个角色」，**只补空缺，不覆盖你已写的新字段**。
保存时也会把新结构同步回这几个旧字段，所以降级回老版本程序也不会读坏。

优先级：命令行参数 > 环境变量（`VTG_` 前缀）> `config.json` > 内置默认值。

**关于 API Key 的安全**：在软件「设置」里填的 Key 会**明文**存进项目根目录的 `config.json`
（桌面软件普遍这么做，因为本机没有安全的密钥服务）。所以：

- 不要把 `config.json` 传给他人或上传到代码仓库（`.gitignore` 已经排除它）；
- 如果不想落盘，改用环境变量：`set VTG_LLM_API_KEY=sk-xxx` 后再启动；
- 怀疑泄露就去厂商控制台吊销重发。

`disable_thinking` 说明：gemma-4、Qwen3 这类「会先思考」的模型，默认会先输出一大段推理过程，
把 token 预算吃光，导致正式答案是空的。关掉之后同一张截图从 37 秒降到 5 秒，结果质量不变。
如果你的模型不支持这个参数，它会被自动忽略，不影响运行。

## 七、打包版（不想装 Python 时用）

`dist/VideoToGuide/VideoToGuide.exe` 是打包好的桌面程序，双击即用，整个目录可以拷到别的路径。

便携版**已经把运行需要的东西都打进去了**，解压即可用：

| 组件 | 要不要 |
| --- | --- |
| Python 运行时 | **已内置**（PyInstaller 打包） |
| 抽帧 / 视频信息读取 | **已内置**（PyAV） |
| 语音识别 | **已内置**（faster-whisper + small 模型，464 MB） |
| FFmpeg / FFprobe | **不需要**（内置读取打不开冷门格式时才兜底） |
| analysis-video | **不需要** |
| 模型服务 | 唯一的外部依赖：本机 LM Studio / Ollama / llama.cpp，或云端 API Key |

包体约 **810 MB**。只想分析无音轨的录屏，可以自己做一个不含 `models/` 目录的精简包，
体积能降到约 350 MB（有旁白的视频会提示转录不可用，其它功能正常）。

打包版和源码版的差异：

- `runs/` 和 `config.json` 都在**程序目录**下，不在项目根目录；
- 没有控制台窗口，命令行模式的输出写进 `runs/logs/exe_cli.log`；
- 也能当命令行用：`VideoToGuide.exe analyze "视频.mp4"`、`VideoToGuide.exe doctor`。

### 首次使用（便携版）

1. 解压到任意可写目录，双击 `VideoToGuide.exe`；
2. 启动一个本地模型服务（LM Studio / Ollama / llama.cpp），或在设置里填云端 API Key；
3. 菜单「工具 → 环境检查」确认软件环境全绿、AI 服务就绪；
4. 选视频 → 开始分析。

## 八、许可与隐私

- 本程序自身代码：见 `LICENSE`；
- 所有视频、截图、转录文本都只存在本机 `runs/` 目录，不联网、不上传；
- 默认调用本机模型服务（127.0.0.1），不产生任何外部 API 费用；
- **如果你主动在「设置」里改用云端模型**，截图和转录文本会发给你选的那家厂商
  （这是它识图的前提），此时数据不再只留在本机。默认配置不会联网。
